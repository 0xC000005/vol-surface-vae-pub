## 293f / 293g / 293h comparison

### Context
The `293` family moved from support-representation search to support-use search.

This bracket is the clean support-use sequence:
- `293f`: best support-object compromise before changing support use
- `293g`: residual law around a direct daily level-pull scaffold
- `293h`: residual law around the scaffold's own increment schedule

The question is whether stronger support use opens a real path, or whether it just creates a new tradeoff.

### Score trajectory
- `293f`: `4/11`
- `293g`: `4/11`
- `293h`: `4/11`

So the support-use subfamily changed behavior, but did not move the frontier.

### What 293g proved
`293g` was the first clear proof that the scaffold was no longer being ignored.

Relative to `293f`, it improved:
- cointegration ratio
- level-side metrics
- extreme-jump scale

But it did that by over-anchoring:
- change KS collapsed
- aggregate MR overshot badly
- regime-width timing inverted

So direct level-pull support use is too strong.

### What 293h proved
`293h` changed only the support-use geometry:
- scaffold increment schedule instead of direct daily pull

That recovered:
- change KS back to `25/25`
- cross-cell structure back into a cleaner regime

But it still did not solve:
- dead level KS
- MR overshoot
- weak regime differentiation

So the geometry change matters, but it still does not break the core path-shape bottleneck.

### Mechanism conclusion
The support-use subfamily is now close to a local cap.

Why:
- `293f` showed support representation alone is not enough
- `293g` showed strong support use changes behavior but over-anchors
- `293h` showed a better support-use geometry restores the local law, but still does not solve the dead suites

That means the branch is no longer missing:
- another support object
- or another immediate support-use geometry tweak

It is missing a stronger path-shape mechanism class.

### Decision
Treat the explicit support branch as near a local cap.

The next principled step should be **research ideation for the next mechanism class**, not another local support variant.

The open design question is:
- what mechanism can control long-horizon path shape directly,
- without collapsing the local stochastic law the way stronger scaffold control does here?
