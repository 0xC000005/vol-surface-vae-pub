# 621a Encoded-State Coordinate Reset

## Context

620a closed the simple deterministic mean-rollout loss branch. The remaining problem is not another obvious architecture knob: one-step likelihood gives broad coverage but poor path placement, one-shot unified path flow lost local structure, and final-path energy/Wasserstein finetuning narrowed the deck.

The user objective now emphasizes a risk-manager-deployable model that is still general:

- IV-only should be a supported special case;
- 25 IV cells plus 13 anchor factors should be generated by one shared model;
- preprocessing may change, but the architecture should not split IV and factors into separate scenario decks.

## Data-Framing Finding

The unified panel utility from 576a already defines a principled transform per variable:

- IV surface cells: `log_level`;
- positive anchor factor levels with matching returns: `log_level`;
- signed or nonpositive factors: `diff_level`;
- return-like columns are not duplicated as separate targets when a level target exists.

It also builds encoded increments and can reconstruct raw future states exactly from encoded increments.

However, the recent native joint AR scripts select `block.history_state` and `block.future_state`, which are raw states. The model then applies empirical normal scores to those raw states and learns score increments. That is generic, but it ignores the more stationary encoded coordinate that the unified panel design already intended.

This is not an evaluator hack and not an IV-specific rule. It is the standard financial state-space framing: model transformed levels in a coordinate where additive increments are meaningful, then decode generated states back to business units.

## Why This Is The Principled Next Move

The stable failures are level occupancy, regime/tail allocation, and mean-reversion/path placement. Those are exactly the quantities most sensitive to state coordinate. If raw factor/IV levels are quantile-scored directly, the AR transition sees rank movement in raw level space rather than log-level or signed-difference dynamics. That can preserve daily KS while misplacing long-horizon levels.

This move keeps the architecture clean:

- one state panel;
- one memory encoder;
- one transition law;
- one stochastic rollout;
- no separate IV/factor heads;
- no post-hoc deck gluing;
- no hand-built stress templates.

It also answers the anchor-factor concern directly: the decoder should not output independent raw factor levels as a glued product. It should output generated transformed states through the same transition mechanism, then decode them to factor levels. Anchor factor returns are implied by generated decoded levels or transformed increments.

## Proposed 622a Falsifier

Add a `value_coordinate` option to the native joint AR flow training/evaluation path:

- `raw`: current behavior;
- `encoded`: train and sample in `encode_state(...)` coordinates from the 576a variable specs.

For evaluation:

- feed encoded validation history to the model;
- sample encoded future states;
- decode generated panel states with `decode_state(...)`;
- pass only decoded IV cells to the official IV bridge;
- keep the state specs in the checkpoint so IV-only and joint38 are reproducible.

Run the smallest decisive comparison first:

- same 610a-style generic AR transition-flow model;
- `state_scope=joint38`;
- `value_coordinate=encoded`;
- no conditional source scale;
- no mean-rollout auxiliary loss;
- same broad 441-window official IV bridge.

## Acceptance Read

This is worth keeping only if it improves the native joint route without losing its structural strengths:

- must preserve surface, block-AR, cointegration, cross-cell, and pathwise quality as much as 610a;
- should improve at least one of level KS, conditionality, regime coverage, mean reversion, or broad coverage;
- if it simply ties or worsens 610a, close the encoded-coordinate route and stop treating preprocessing as the missing mechanism.
