# 656a Empirical-Copula Joint Anchor Factor Deck

## Question

The 574a joint deck paired selected IV scenarios with anchor-factor scenarios by the same severity quantile. That guarantees aggregate severity alignment, but it can suppress historically observed mixed cases such as calm-IV plus stressed-factor, or stressed-IV plus calm-factor.

656a tests a more defensible stress-deck pairing:

1. Select the IV deck exactly as before from the 510a/568a risk-manager IV scenario generator.
2. Estimate a pre-deck historical rank copula between 30-day future IV severity and 30-day future anchor-factor stress.
3. For each selected IV severity rank, sample a factor stress rank from the historical conditional distribution `P(factor_stress_rank | IV_severity_rank_bucket)`.
4. Select generated panel-law factor paths whose anchor-factor stress rank matches the sampled target rank.

This is still a stress-deck composition, not a calibrated joint probability law. The improvement over 574a is that the composition no longer forces a diagonal IV/factor severity copula. That is useful as a diagnostic, but it does not solve the core scientific concern: IV and anchor factors are still generated by different mechanisms and then paired after generation.

## Result

Command:

```bash
python experiments/backfill/block_ar/generate_573a_joint_anchor_factor_deck.py \
  --factor_pairing_policy empirical_copula_factor_stress \
  --copula_bins 3 \
  --seed 656 \
  --output_npz results/autoresearch/656a_empirical_copula_joint_anchor_factor_deck/joint_anchor_factor_deck.npz \
  --output_manifest results/autoresearch/656a_empirical_copula_joint_anchor_factor_deck/manifest.json
```

The deck generated successfully with 48 scenarios, 30-day horizon, 25 IV cells, and 26 anchor-factor channels.

Key manifest diagnostics:

- `factor_pairing_policy`: `empirical_copula_matched_to_factor_stress_severity`
- `historical_copula_windows`: `5763`
- `selected_rank_corr`: `0.478231`
- `historical_rank_corr`: `0.457686`
- `selected_mixed_bucket_rate`: `0.520833`
- `historical_mixed_bucket_rate`: `0.524900`
- `selected_same_bucket_rate`: `0.479167`
- `historical_same_bucket_rate`: `0.475100`
- `factor_selected_stress_quantiles` closely track `factor_target_stress_quantiles` in the output NPZ.

For comparison, 574a had `mean_abs_quantile_error=0.0` because it forced selected IV severity quantiles and factor severity quantiles to be identical. That is useful for a diagonal severity stress deck, but it is not evidence that the historical IV/factor copula was preserved. 656a sacrifices zero rank error by design and instead matches the historical mixed-rank structure.

## Interpretation

This answers the risk-manager concern more cleanly:

- We do not use every permutation, so we are not inventing arbitrary co-movement states.
- We also do not force same-rank IV/factor pairing, so we do not miss historically common mixed-rank states.
- The selected deck reproduces the historical pre-deck mixed-bucket rate almost exactly at the coarse three-bucket level.

## Decision After Review

656a should not be promoted as the core deployable or publishable methodology.

The user correctly identified the remaining problem: the factor scenario is not born from the same conditional mechanism as the IV scenario. The empirical copula makes the pairing less arbitrary than 574a, but it is still a post-hoc story about two separately generated objects. That is hard to justify as a generalizable conditional scenario generator, especially when the stated long-term goal is to add more factor types without hand-designed composition rules.

Keep 656a as a diagnostic/falsification baseline:

- It shows that same-rank pairing is too restrictive because historical mixed IV/factor rank states are common.
- It provides a stress-deck overlay if a risk manager explicitly wants policy scenarios rather than a learned joint law.
- It should not be marketed as evidence of a unified conditional joint probability model.

The principled next path is a native joint generator: one model state, one stochastic source, all channels generated together, with type-aware preprocessing/readouts allowed only because units differ. The story should be that the model learns the conditional joint movement of the whole market panel, not that we generate IV first and attach factor stories afterward.
